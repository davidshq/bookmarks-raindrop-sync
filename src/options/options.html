    Settings

    Uploads browser bookmarks → Raindrop only. Below, choose whether to keep a local copy after a confirmed upload, or offload (delete locally).

    Keeps bookmarks in both the browser and Raindrop: pulls Raindrop → browser under your root, and propagates user deletes both ways. Raindrop-only metadata (tags, notes, highlights) is never overwritten from the browser.

    Deleting a bookmark in the browser or Raindrop removes the paired item in the other system. To offload a specific folder (upload then remove locally only), set that folder’s policy to Offload (delete locally) under Folder policies — that cleanup does not delete Raindrop.

    • Delete locally — After a confirmed upload, remove the local bookmark. Raindrop keeps the copy. This is the default for one-way offload.
    • Keep locally — Leave the browser bookmark after upload (mirror, don’t clear local).
    • Exclude — Do not sync by default; use folder policies to opt folders in.

    Global default is keep in both places. Use folder policies for exceptions: Exclude a subtree, or Offload (delete locally) for folders you still want cleared locally after upload.

    How often to start a full Raindrop check when confirm catch-up is settled. Each heartbeat prefers draining the sync queue, then uses leftover Raindrop budget for Trash / list work — queued jobs do not hard-block listing. Unfinished missing-raindrop checks continue every minute. Use Pull now for an immediate check.

    Pull bookmarks only into folder paths that already exist in the browser, unless you opt in Raindrop-only collections under Folder policies. Unchecked Raindrop-only paths are skipped (no catch-all).

    When pulling a bookmark, create missing browser folders along its collection path. Empty Raindrop collections stay invisible unless you check them under Folder policies. Once any Raindrop-only collection is checked, only checked ones sync.

    Like create-as-needed, and also create browser folders for empty Raindrop collections under your root—unless a Raindrop-only allowlist is set under Folder policies, which then limits sync to checked collections.

    Manual Sync

    Sync to Raindrop

    Uploads bookmarks already in the browser that are not synced yet, and skips folders set to Exclude. Large or thinly paired libraries are detected and you may be asked to Match from Raindrop export first. Does not pull from Raindrop.

    Last push: —

    Pull from Raindrop

    Brings new and changed Raindrop bookmarks into the browser, and removes local bookmarks whose Raindrop copy is gone. Quiet-time pulls also run on your interval. Large libraries with low pair coverage may prompt to Match from export first. Does not upload existing browser bookmarks.

    Last pull: —

    Match existing from export

    Power-user: download Raindrop export.csv, match by URL, record pairs only. Import/Pull usually prompt automatically when the library looks like a bulk candidate. Does not upload, pull, move, or delete bookmarks.

    Folder policies

    Override the default for a folder and everything beneath it (nearest folder wins). Options: Keep locally, Offload (delete locally after upload), or Exclude. Nested folders start collapsed (toolbar / other bookmarks roots stay open). Use Expand all / Collapse all or the filter to find deeper folders. Overrides survive renames. Edits stay local until you apply (sticky bar below). Raindrop-only collections are opted in via the section at the bottom (bidirectional only)—not in this browser tree.

    Choose Raindrop-only collections to sync

    All Raindrop collections that are not fully present in the browser (entire account, not only under the sync root). Check to create the folder and pull items. Folders outside the sync root land under Other bookmarks / Raindrop; bookmarks you add there upload back to that Raindrop collection. New collections stay unchecked. Once any are checked, only checked Raindrop-only paths sync. Select all checks every listed collection; Clear selection exits selective mode (then apply). Reconcile does not clear checked collections when folders appear — only when they disappear from Raindrop. Takes effect with Apply folder policies.
